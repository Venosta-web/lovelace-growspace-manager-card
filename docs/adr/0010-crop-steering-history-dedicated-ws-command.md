# Crop Steering Day Chart fetches history via a dedicated WS command, not history-store

The [[Crop Steering Day Chart]] needs Substrate VWC, Pore EC, and Bulk EC readings bucketed onto a fixed calendar-day axis anchored at `lightsOnMin − 120` — matching the Phase Strip above it — including a partial day when "today" is still in progress. The existing `history-store` only offers rolling windows (`1h | 6h | 24h | 7d`), which don't align to a photoperiod boundary and can't represent "since lights-on, 2 hours back, through to now, with the rest of the day empty."

We added `growspace_manager/get_crop_steering_history`, mirroring the `get_tank_water_history` pattern: the backend does the bucketing and anchoring (it already knows `lightsOnMin` and the configured sensor entity ids), and returns a ready-to-plot series per metric. The alternative — fetching `history-store`'s 24h rolling window and remapping/clipping it onto the lights-on axis client-side — was rejected because the rolling window can straddle two different photoperiods (if "now" is shortly after lights-on, the most relevant data is in *yesterday's* tail of the 24h window), making the remap logic fragile and duplicating anchoring knowledge the backend already has.
